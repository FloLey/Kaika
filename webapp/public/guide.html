Kaika 開花 — Guide

Transformer un morceau de musique en clip vidéo : du son, un fluide ; du fluide, une fleur.

Lancement

Kaika est une application locale : un serveur Python + une interface web.

kaika serve     # lance le serveur sur http://localhost:8400
kaika           # pareil, et ouvre le navigateur

Avec Docker : docker compose up à la racine du dépôt.

Concepts

Le pipeline transforme l'audio en vidéo en plusieurs étapes :

  1. Analyse — tempo, beats, onsets (attaques par bande de fréquences), sections (intro/couplet/refrain/drop…) et signaux par frame (énergie, brillance, flux spectral…).
  2. Simulation — un fluide 2D (de l'encre dans un courant) est « dansé » par ces signaux : des émetteurs injectent de l'encre sur les événements musicaux, des modulateurs font respirer la physique.
  3. Post — les frames deviennent un MP4 muxé avec l'audio (et les sous-titres de paroles le cas échéant).
  4. Diffusion (optionnelle) — un modèle vidéo re-texture le fluide en formes organiques guidées par les prompts de chaque segment.

Les objets que vous manipulez

ObjetCe que c'est
RecetteL'identité visuelle : canvas, physique du champ (field), émetteurs, palettes, modulateurs, rendu, paroles. Des recettes de départ existent (eclosion, encre) ; tout est modifiable ensuite.
ProjetUn morceau + sa recette + ses segments + sa timeline. Chaque projet vit dans son dossier runs/<id> et garde un historique de révisions (chaque action est annulable).
SegmentUne tranche temporelle du morceau (détectée à l'analyse, modifiable) avec son nom, son prompt de diffusion et ses surcharges de recette.
TimelineDes directives ponctuelles posées sur le temps : spawn d'encre, fenêtre de valeurs, mute d'un émetteur, texte… (détail).

La boucle de travail : éditer → la fenêtre de preview se re-rend en quelques secondes → écouter/regarder → recommencer. La diffusion finale n'arrive qu'à la toute fin.

Créer un projet

  1. Onglet Studio : glissez un fichier audio dans la zone (ou Choose file).
  2. Choisissez l'identité visuelle de départ (la recette).
  3. Optionnel : collez les paroles — texte brut ou format .lrc. Elles sont alignées automatiquement sur la piste en arrière-plan (détail).

L'analyse découpe le morceau en segments éditables et le Studio s'ouvre avec un premier preview.

Astuce : les paroles collées depuis Genius sont nettoyées automatiquement (marqueurs [Refrain], ad-libs entre parenthèses, bloc « You might also like »).

Le Studio : vue d'ensemble

Trois zones :

  • À gauche — les segments : la colonne vertébrale du morceau. Sélection, renommage, prompts, découpage (détail).
  • Au centre — le preview : la fenêtre vidéo en boucle, le transport audio, la waveform et les lanes de signaux (détail).
  • À droite — le panneau contextuel : bascule entre ✨ Assistant (suggestions + chat) et ⚙ Réglages (l'inspecteur de la recette).

Segments

Chaque segment affiche son label coloré (intro, verse, chorus, drop…) et ses bornes. Cliquer un segment lance son preview.

Le segment sélectionné se déplie pour l'édition :

  • Name — le label (sert aussi d'ancre de section pour la timeline).
  • Prompt (diffusion) — comment cette section doit devenir une fois diffusée (« encre qui fleurit en pivoines », « nébuleuse violette »…). Utilisé uniquement à l'étape diffusion.
  • Split at playhead — coupe le segment à la position de lecture ; Merge next — fusionne avec le suivant. (Durée minimale d'un segment : 0,4 s.)
  • Advanced overrides — un YAML fusionné par-dessus la recette globale pour ce segment seulement : 
    field:
  vorticity: 30
render:
  bloom: 1.4
    Les transitions entre segments sont lissées automatiquement.
  • ⚙ Tune this segment — bascule le panneau de droite en mode Réglages.

En bas du rail : Preview full track (simulation fluide du morceau entier, sans diffusion) et Generate (diffusion) — voir Rendu & diffusion.

La fenêtre de preview

Le cœur de la boucle d'édition : une fenêtre d'environ 6 secondes autour de la tête de lecture, re-simulée en qualité brouillon à chaque modification, qui boucle en vidéo.

  • live preview (case à cocher du transport) — quand elle est active, toute édition (slider, segment, chat…) relance le rendu de la fenêtre. Décochez-la pour éditer en rafale sans déclencher de jobs.
  • Déplacer la tête de lecture (clic sur la waveform) recadre la fenêtre (1 s avant la position, 5 s après).
  • Pendant le calcul, la dernière frame simulée s'affiche en surimpression : on voit le rendu arriver.
  • HQ window — re-rend la même fenêtre en pleine résolution (utile pour juger les détails avant un rendu complet).
Une seule source audio : le son sort de la vidéo de preview elle-même (sa bande-son est l'extrait exact du morceau), et la tête de lecture est toujours synchronisée dessus. Cliquer sur la waveform dans la fenêtre rendue cale la vidéo à l'instant exact ; cliquer en dehors re-rend la fenêtre autour du nouveau point.

Waveform & signaux

La waveform montre le morceau entier avec ses segments colorés, le quadrillage des beats et les onsets détectés.

  • Clic — déplace la tête de lecture (et recadre le preview).
  • Glisser une frontière de segment — ajuste le découpage.
  • ▶ — lance / met en pause la lecture. Le son vient de la vidéo de preview (une seule source audio) ; la tête de lecture la suit en permanence.

Les lanes

Sous la waveform, trois pistes montrent ce qui pilote la simulation :

  • rms / flux — l'énergie globale (aire) et le flux spectral (ligne) : c'est ce que « ressentent » les modulateurs.
  • bands low/mid/high — la répartition basses/médiums/aigus, qui déclenche les émetteurs par bande.
  • timeline — les directives posées sur le temps, sous forme d'épingles déplaçables à la souris.

Timeline : les directives

La timeline pose des événements ponctuels par-dessus le comportement continu de la recette. Elle s'édite via le chat, les suggestions, l'onglet Motion des réglages, ou en déplaçant les épingles de la lane.

ActionEffetExemple
spawnInjecte de l'encre à un instant donné (avec placement, couleur, force…). {at: 12.5, action: spawn, count: 3}
setChange des valeurs de recette sur une fenêtre [t0, t1], avec fondu d'entrée/sortie (fade_s). {action: set, between: [30, 45], set: {field.vorticity: 25}}
mute / unmuteCoupe / réactive un émetteur à partir d'un instant. {at: 60, action: mute, emitter: kick}
textStampe un texte dans le fluide (l'encre forme les lettres puis le courant les emporte). {at: 8, action: text, text: "KAIKA"}

Le champ at (ou les bornes de between) accepte des secondes ou des ancres musicales qui suivent le morceau si le tempo ou les sections bougent :

  • section:drop — le début de chaque section nommée drop (s'applique à toutes les occurrences) ;
  • beat:32 / bar:8 — un beat ou une mesure précise ;
  • un décalage est possible : section:chorus+1.5.

Raccourcis clavier

Actifs dès qu'un projet est ouvert, sauf quand le curseur est dans un champ de texte. Ils ont priorité sur les raccourcis natifs de la vidéo — la vitesse de lecture est verrouillée à 1×.

ToucheAction
EspaceLecture / pause
← / → Reculer / avancer de 1 s (Maj : 5 s)
↑ / ↓ Segment précédent / suivant (et son preview)
S Couper le segment à la tête de lecture (split)
M Fusionner le segment sélectionné avec le suivant (merge)
H Rendre la fenêtre courante en pleine résolution (HQ)
L Activer / couper le live preview

Suggestions ✨

Le directeur artistique : le LLM analyse la structure du morceau (et les paroles si présentes) et propose un look global + une proposition par segment, chacun avec son raisonnement et la liste des changements.

  1. Optionnel : donnez une direction dans le champ (« darker », « more energetic », « palette froide »…).
  2. ✨ Propose ideas — génère le plan.
  3. Sur chaque carte : Preview teste la proposition sans rien appliquer (rendu d'un segment représentatif) ; Accept l'applique (annulable) ; Reject l'écarte.

Les propositions par segment sont conçues par-dessus le look global — accepter le global d'abord donne le résultat le plus cohérent.

Prérequis : une clé API configurée dans les Settings.

Le chat copilote

Décrivez un changement en langage naturel ; le copilote édite le projet uniquement à travers des outils validés — il ne peut pas casser la recette, chaque modification passe par la validation du schéma.

Exemples de demandes :

  • « à 2 secondes, je veux 3 sources alignées horizontalement au centre »
  • « rends le drop plus violent »
  • « passe la palette principale dans des bleus profonds »
  • « coupe l'émetteur kick pendant l'intro »
  • « preview le refrain »

Ce qu'il sait faire : lire le projet et l'analyse audio, modifier toute valeur de la recette, gérer les émetteurs / palettes / modulateurs / canvas, découper et régler les segments, poser des directives timeline, lancer un preview ou le rendu final.

  • Chaque tour qui modifie le projet crée une révision : les changements s'affichent en puces avec un bouton Undo.
  • L'historique de conversation est conservé par projet.
Prérequis : une clé API configurée dans les Settings (Anthropic ou Gemini).

Réglages : l'inspecteur

Le mode ⚙ du panneau de droite expose toute la recette, en formulaires générés depuis le schéma. Quatre onglets :

Look

  • Palettes — les jeux de couleurs nommés que les émetteurs référencent.
  • Render — bloom, fond, contraste… l'apparence du fluide.
  • Canvas — résolution et format, avec presets 1:1, 9:16 (vertical) et 16:9.

Emitters

Les sources d'encre. Chaque émetteur combine un déclencheur (onset par bande, beat, lookahead de section…), un placement (pad 2D, point fixe, aléatoire, suivi d'un signal…), une direction, une couleur (palette, cycle, pitch chromatique…) et un corps (rayon, force, durée de vie, débit). Des templates donnent un point de départ : kick jet, scatter pops, pitch line, beat pulse, tension.

Motion

  • Field — la physique : vorticity (tourbillons), dissipation, viscosité, brassage ambiant…
  • Modulators — relient un signal audio à un paramètre : rms → field.ambient.strength fait respirer le courant avec l'énergie du morceau. Signaux disponibles : rms, centroid, flux, beat_phase, bar_phase, harmonic_ratio, chroma_argmax, band.low/mid/high, section.energy, voice.

YAML

La recette complète, éditable en texte. Validée à l'application — une erreur de schéma est refusée avec son message, rien n'est perdu.

Épingles et badges

  • L'icône 📌 sur un champ l'épingle : un slider apparaît dans le bandeau au-dessus du preview, pour garder vos paramètres de session sous la main.
  • Le badge mod signale un paramètre piloté par un modulateur : sa valeur de base est déplacée en continu par le signal.

Paroles

Collées à la création du projet, les paroles servent à deux choses : l'affichage (sous-titres ou texte dans le fluide) et l'analyse (la structure du morceau est re-dérivée des paroles alignées : sections + activité vocale).

Formats

  • Texte brut — aligné automatiquement par reconnaissance vocale (Whisper). Le premier alignement télécharge le modèle (réseau requis une fois, ensuite c'est en cache). L'alignement tourne en arrière-plan ; le Studio l'indique sous le preview.
  • .lrc — déjà horodaté, utilisé tel quel, instantané.

Nettoyage automatique

Le texte collé est nettoyé avant alignement :

  • les marqueurs de section [Couplet 1], (x2)… ;
  • les ad-libs entre parenthèses, en ligne (Sûrement (Sûrement) → Sûrement) comme en lignes entières ;
  • le bloc « You might also like » + titres suggérés qu'insère Genius.

Affichage

Dans la recette, section lyrics (onglet Look ou YAML) :

ChampEffet
enabledActive l'affichage — activé par défaut : les paroles apparaissent sur les previews et le clip final dès qu'elles sont alignées.
modeoverlay = sous-titres nets incrustés ; fluid = chaque ligne stampée en encre dans la simulation à son timestamp (le courant l'emporte) ; both = les deux.
position, scale, color, outlinePosition (bottom / lower_third / center / top), taille, couleur, contour des sous-titres.

Rendu & diffusion

Deux sorties, depuis le bas du rail de segments :

  • Preview full track — simule le fluide sur tout le morceau, en vraie qualité mais sans diffusion. Rapide ; c'est le bon juge du mouvement.
  • Generate (diffusion) — le pipeline complet : le fluide est re-texturé par le modèle de diffusion vidéo, guidé par le prompt de chaque segment. C'est l'étape longue (GPU requis côté diffusion).

L'onglet Render suit le job en direct : barre par étape (analyze → simulate → control → diffuse → post), frame en direct pendant la simulation, bouton Cancel. À la fin :

  • résultat fluide → bouton Generate final (diffusion) pour enchaîner ;
  • clip final → See in Gallery.
File de jobs : les rendus passent un par un. Un nouveau preview de fenêtre annule automatiquement le précédent sur le même projet.

Galerie

Tous les runs avec leur vignette vidéo, la recette utilisée et le statut (fluide seul ou clip final).

  • Open in Studio — rouvre le projet pour continuer à l'éditer.
  • Compare — cochez deux runs : ils se lisent côte à côte sur le même transport, parfait pour juger l'effet d'un changement de paramètre.

Settings ⚙

Le bouton ⚙ en haut à droite configure le LLM utilisé par le chat et les suggestions :

  • Provider — Anthropic (Claude) ou Google (Gemini).
  • Model — laissez vide pour le modèle par défaut du provider.
  • Clés API — stockées côté serveur (.kaika/settings.json), jamais renvoyées au navigateur (l'interface indique seulement « set ✓ »).

Dépannage

SymptômePiste
Le preview ne se met pas à jour après une édition. Vérifiez la case live preview du transport ; sinon déplacez la tête de lecture ou cliquez un segment pour relancer une fenêtre.
« lyrics alignment failed » La piste n'a peut-être pas de voix exploitable, ou le premier téléchargement du modèle Whisper a échoué (réseau requis une fois). Le projet reste utilisable sans paroles.
Le chat ou les suggestions renvoient une erreur de clé. Configurez le provider et sa clé API dans les Settings.
La simulation est lente. Le preview de fenêtre est déjà en qualité brouillon ; pour le rendu complet, un GPU NVIDIA accélère la simulation avec KAIKA_GPU=1 (CuPy installé).
Une édition a tout cassé. Chaque modification (UI, chat, suggestion) crée une révision — Undo dans le chat restaure l'état précédent.
